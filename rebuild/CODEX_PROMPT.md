# 交给 Codex 的执行提示词

你现在要在现有 Ygrowly 个人网站仓库中重构首页。设计已经确定，你负责按规格实现、验证和修复，不负责重新做产品或视觉决策。

## 必读文件

按顺序完整阅读：

1. `docs/homepage-redesign/README.md`
2. `docs/homepage-redesign/01-content-and-structure.md`
3. `docs/homepage-redesign/02-visual-system.md`
4. `docs/homepage-redesign/03-components-and-interactions.md`
5. `docs/homepage-redesign/04-implementation-plan.md`
6. `docs/homepage-redesign/05-acceptance-checklist.md`

如果这些文件不在该路径，先在仓库中查找同名文件，不要跳过。

## 核心约束

- 保留现有框架、包管理器、内容系统和部署方式。
- 保留 `/en` 双语路由。
- 保留 Light/Dark 主题与持久化逻辑。
- 保留并复用现有 Terminal、DevMode、虚拟文件系统和命令系统。
- 不创建第二个假 Terminal。
- 首页重点项目固定为 EnergyOps Agent、数驭穹图 AI BI。
- PayTrace 只放 `Lab & Open Source`，标注 `Building`。
- 项目剧场是局部深色章节，不能修改全局主题状态。
- 简历稳定路径固定为 `/resume.pdf`、`/resume-en.pdf`。
- 不引入新 UI 框架、CSS 框架、轮播库或通用动画库。
- 不使用头像主视觉、蓝紫渐变、WebGL、粒子、自定义鼠标、滚动劫持、技能进度条或卡片墙。
- 不虚构项目数据、测试数字、演讲规模、英文文章或企业截图。
- 不覆盖用户现有的无关修改。

## 执行方式

严格按 `04-implementation-plan.md` 的 M0 到 M6 执行。

第一步只做 M0 只读盘点，输出“规格职责 → 现有文件/组件 → 处理方式”的映射表，并检查工作区修改、简历文件和验证命令。

只有在以下情况才暂停询问：

1. 找不到或存在两套 Terminal/DevMode，无法判断哪套为正式实现；
2. `/en` 的真实结构与规格前提冲突；
3. 简历文件和稳定路径冲突；
4. 企业项目内容可能泄露敏感信息；
5. 与本任务重叠的用户修改无法安全保留；
6. 缺少必须由用户提供的真实资产或内容，且规格没有定义文字降级方案。

除此以外，不要反复询问技术实现细节；使用现有项目模式完成等价实现。

## 修改规则

- 优先修改现有组件，不重复造轮子。
- 数据和文案集中管理，不散落硬编码。
- Blog、Notes 使用现有内容集合的确定性查询规则。
- Terminal 只扩展公开命令和首页展示，不重写核心解析器。
- 若没有脱敏项目截图，使用规格中的文本证据面板，不寻找图库图片，不生成随机图。
- 测试数字只有实际运行对应测试后才能更新。
- 每个里程碑完成后运行与该阶段相关的最小验证；最后运行全部验证。

## 最终交付

完成后提供：

1. 可见结果摘要；
2. 修改文件列表；
3. 规格职责与实现文件映射；
4. M0–M6 每阶段完成情况；
5. 实际执行的格式化、lint、类型检查、测试、构建命令和结果；
6. 六个规定视口的检查结果；
7. `05-acceptance-checklist.md` 中未通过项；
8. 缺失内容、素材或后续工作；
9. 明确说明未实现项，不能用模糊措辞隐藏。

先执行 M0，给出盘点和实施计划，然后继续实现；只有命中上述阻塞条件时才暂停。
