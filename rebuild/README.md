# Ygrowly 个人网站首页重构：Codex 实现规格

版本：v1.0  
日期：2026-07-27  
目标：把现有个人网站重构为兼顾求职转化、工程可信度和长期个人品牌的双语工程师主页。

## 1. 使用方式

将本目录完整放入网站仓库的 `docs/homepage-redesign/`，让 Codex 按以下顺序阅读：

1. `README.md`
2. `01-content-and-structure.md`
3. `02-visual-system.md`
4. `03-components-and-interactions.md`
5. `04-implementation-plan.md`
6. `05-acceptance-checklist.md`
7. `CODEX_PROMPT.md`

本规格已经完成产品和视觉决策。Codex 的职责是：

- 对照现有代码找到对应路由、组件、数据源和主题变量；
- 在现有技术栈内实现；
- 保留现有可复用能力；
- 按验收标准测试和修复。

Codex 不得重新设计信息架构、项目排序、配色、字体、圆角、动画方式或响应式策略。

## 2. 网站目标

网站采用“双速阅读”：

- 30 秒：HR 能确认姓名、方向、届别、经历、城市偏好、简历和联系方式；
- 3～5 分钟：技术面试官能确认项目链路、个人职责、工程难点和可验证证据；
- 深入浏览：同行和普通访客能看到写作、开源、分享和个人审美。

首页叙事固定为：

```text
我是谁、在找什么
→ 我做过哪些真实系统
→ 我的经历和职责是否可信
→ 我在持续构建和开源什么
→ 我如何思考与表达
→ 简历与联系
```

## 3. 不可变设计决策

以下决策不得由 Codex 改写：

1. 中文品牌使用“刘宇广 / Ygrowly”；不把 Quiet Systems Lab 当作公开工作室品牌。
2. 首页首屏为左侧定位文案、右侧真实 Terminal。
3. 保留现有 Terminal、DevMode、虚拟文件系统和命令系统，不另写一个假终端替代。
4. 首页重点项目固定为：
   - EnergyOps Agent
   - 数驭穹图 AI BI
5. PayTrace 放入 `Lab & Open Source`，状态为 `Building`，当前不进入重点项目剧场。
6. 保留现有 `/en` 双语路由体系。
7. 保留现有 Light/Dark 主题切换；项目剧场只是局部深色章节，不能修改全局主题状态。
8. 视觉方向固定为：暖白编辑页面 + 炭黑项目剧场 + 信号青绿。
9. 首页不放头像；头像或插画只在 About 页面使用。
10. 简历入口至少出现在顶部导航、Hero、Contact 三处，稳定路径为：
    - 中文：`/resume.pdf`
    - 英文：`/resume-en.pdf`
11. 首页只使用一个 Sticky Scroll，即 Selected Systems。
12. Writing 使用静态编辑式分栏，不做自动轮播或叠卡。

## 4. 保留、重构与删除

### 必须保留

- `/en` 路由及语言切换逻辑；
- Light/Dark 主题及持久化逻辑；
- Terminal、DevMode、虚拟文件系统和已有命令；
- 现有 Blog、Notes 内容集合及详情路由；
- 现有项目、经历、About 数据中真实有效的内容；
- SEO、RSS、sitemap 等已有能力。

### 允许重构

- 首页布局和区块顺序；
- 导航的展示标签与响应式结构；
- 首页项目卡、经历行、写作卡、联系区；
- Terminal 在 Hero 中的外观、默认输出、命令别名和跳转行为；
- 颜色、间距、排版和组件状态变量；
- 首页中项目与文章的选取逻辑。

### 明确删除或禁止新增

- 首页头像主视觉；
- 技能标签墙和熟练度进度条；
- 蓝紫色 AI 渐变；
- 全站滚动劫持、强制平滑滚动；
- 自定义鼠标；
- WebGL、粒子、全屏 3D；
- 首屏加载动画；
- 大段逐字出现；
- 自动播放音视频；
- 多个自动轮播；
- 所有卡片跟随鼠标倾斜；
- 只有 Hover 才能读到的关键信息；
- 无关图库图片和虚构的企业数据、演讲规模、项目成果。

## 5. 实现边界

- 不更换框架、构建工具、内容系统、包管理器或部署平台。
- 不引入新的 CSS 框架或组件库。
- 优先复用现有组件；只在职责不清或无法复用时拆分。
- 不为了首页重构改写 Terminal 的核心命令解析器或虚拟文件系统架构。
- 不删除旧能力。旧命令若与新命令冲突，保留旧命令并增加别名。
- 若缺少项目视觉素材，不使用图库、AI 随机图或临时插画代替；记录为阻塞项，先使用规范中定义的“文本证据面板”。
- 企业项目信息必须脱敏，不显示内部域名、IP、真实设备编号、手机号、账号、密钥或未公开截图。

## 6. 实现完成的定义

只有同时满足以下条件才算完成：

- 中英文首页均完成；
- Light/Dark 与项目剧场正确共存；
- Terminal 静态首屏、轻量演示和真实交互均工作；
- 两个重点项目在桌面与移动端均可完整阅读；
- 简历、GitHub、邮箱、项目、文章入口可用；
- 键盘、屏幕阅读器和 reduced-motion 基本可用；
- 指定视口无横向溢出、遮挡、跳动和内容截断；
- 现有构建、测试、类型检查通过；
- `05-acceptance-checklist.md` 中 P0、P1 项全部通过。
