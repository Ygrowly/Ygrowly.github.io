# 04：Codex 实施计划

## 总原则

按 M0 → M6 顺序实施。每个里程碑完成后先验证，再进入下一步。不得一次性重写整个首页后再集中排错。

## M0：现状盘点与映射

只读检查，不改代码。

Codex 必须输出：

1. 框架、包管理器、构建命令；
2. 首页、中英文首页、About、项目详情、Blog、Notes 的真实路由文件；
3. 全局布局、导航、主题、i18n 的真实实现文件；
4. Terminal、DevMode、虚拟文件系统、命令注册器的真实文件；
5. 项目、经历、Blog、Notes 的数据来源；
6. 简历文件是否存在；
7. 现有测试、类型检查、lint、构建命令；
8. `.openai/hosting.json` 是否存在；
9. 当前工作区已有未提交修改，尤其是与本任务重叠的文件。

M0 输出一张映射表：

| 规格职责 | 现有文件/组件 | 处理方式 |
|---|---|---|
| SiteHeader | 实际路径 | 复用/修改 |
| Hero | 实际路径 | 复用/拆分 |
| Terminal | 实际路径 | 保留核心、修改外观与命令 |
| Theme | 实际路径 | 复用 |
| i18n | 实际路径 | 复用 |
| Projects data | 实际路径 | 扩展 |
| Writing data | 实际路径 | 复用查询 |

阻塞条件：

- 找不到 Terminal 或存在两套 Terminal；
- `/en` 不是独立路由而是运行时翻译；
- 简历路径与规格冲突；
- 项目内容包含不能公开的信息；
- 相关文件已有无法安全合并的用户修改。

遇到阻塞时停止相关部分并询问，不自行替换方案。

## M1：全局令牌、页面骨架与导航

实现：

1. 将 `02-visual-system.md` 中颜色、字体、间距、圆角、边框变量接入现有全局样式；
2. 保留现有主题持久化，替换对应视觉变量；
3. 首页建立固定区块顺序和锚点；
4. 重构桌面与移动导航；
5. 接入中英文标签；
6. 接入稳定简历入口。

验收：

- Light/Dark 可切换且刷新后保持；
- 中文、英文导航均无 404；
- 移动菜单键盘可打开/关闭；
- 页面区块顺序正确；
- 暂时没有内容的区块也不能导致布局溢出。

## M2：Hero 与 Terminal

先完成静态 Hero，再增强 Terminal。

步骤：

1. 实现中英文 Hero 文案和三个 CTA；
2. 实现状态行与经历索引；
3. 为 Terminal 预留固定尺寸，确保无布局位移；
4. 将现有 Terminal 放入 Hero；
5. 更新默认静态输出；
6. 注册规格中的新命令或别名；
7. 实现 800ms 后的一条轻量演示；
8. 实现取消演示、sessionStorage 和 reduced-motion；
9. 实现移动端简化视图。

不得：

- 重写命令解析器；
- 删除旧命令；
- 自动聚焦；
- 自动打开简历或 GitHub；
- 在 Terminal 中显示真实文件系统。

验收：

- 禁用 JavaScript 后 Hero 主要信息仍可读；
- Terminal 可真实输入；
- Demo 最长 4 秒；
- 点击或滚动立即取消；
- `help/projects/resume/theme/lang/clear/devmode` 工作；
- 输入历史和 `Ctrl+L` 工作；
- 屏幕阅读器不会逐字播报演示字符。

## M3：Selected Systems

步骤：

1. 建立项目剧场局部主题变量；
2. 填入两个固定项目；
3. 实现项目正文、流程、证据、CTA；
4. 桌面实现 Sticky 证据面板；
5. 移动和平板改为普通纵向内容；
6. 实现导航经过剧场时的局部前景色；
7. 接入真实详情页；
8. 检查脱敏。

如果缺少项目截图：

- 使用文本证据面板；
- 不生成图片；
- 不显示空白媒体容器。

验收：

- 剧场不改变全局主题；
- 两个项目正文始终可读；
- Sticky 不锁滚轮；
- 1023px 以下无 Sticky；
- reduced-motion 无切换动画；
- Light/Dark 下边界和文字对比均清楚。

## M4：Experience、Lab、Writing、Profile、Contact

步骤：

1. 实现三条 Experience；
2. 实现三项 Lab & Open Source；
3. 接入最新 Blog、第二篇 Blog、最新三条 Notes；
4. 有真实数据时展示 Talks & Demos，无内容则隐藏；
5. 实现 Profile 四行信息和主张；
6. 实现 Contact 和 Footer；
7. 中英文内容分别接入。

验收：

- 经历不使用卡片墙；
- 展开内容只有一条重点；
- PayTrace 明确为 Building；
- Blog/Notes 选取规则确定且无草稿泄漏；
- Contact 的邮箱、GitHub、简历可用；
- 英文内容不足时不自动翻译或复制中文正文。

## M5：SEO、无障碍与性能

实现：

1. title、description、canonical、hreflang；
2. Person JSON-LD；
3. 页面语义结构：单一 `h1`，区块使用 `h2`，卡片标题使用 `h3`；
4. Skip link；
5. Focus 状态；
6. Terminal aria-label 与 aria-live；
7. 图片尺寸、懒加载和 alt；
8. 字体本地加载或系统回退；
9. reduced-motion；
10. 移除未使用的首页脚本和动画依赖。

性能边界：

- 首屏 Terminal 不能造成 CLS；
- 非首屏图片默认懒加载；
- 不为了本次重构新增超过 `80KB gzip` 的客户端 JavaScript；
- 若现有 Terminal 本身较大，使用延迟增强，但静态内容先显示；
- 不新增 WebGL、动画或轮播依赖。

## M6：验证与清理

必须运行仓库现有的：

- 格式化检查；
- lint；
- 类型检查；
- 单元测试；
- 构建；
- 如存在 E2E，则运行首页相关 E2E。

增加或更新最少测试：

1. 中英文首页可构建；
2. Blog/Notes 选择规则；
3. Terminal 新命令；
4. Theme 与 theater 状态不互相覆盖；
5. 语言切换 fallback；
6. 移动菜单；
7. 简历路径存在。

人工检查视口：

```text
1440 × 900
1280 × 800
1024 × 768
768 × 1024
390 × 844
375 × 812
```

输出完成报告：

1. 改动摘要；
2. 规格到文件的映射；
3. 每个里程碑验证结果；
4. 自动测试命令与真实输出摘要；
5. 仍存在的内容/素材缺口；
6. 未实现项及原因；
7. 不要只写“已完成”。

## Codex 决策边界

Codex 可以自行决定：

- 现有组件和规格职责的映射；
- 在不改变公开 API 的前提下拆分内部函数；
- 测试文件放置位置；
- 与现有代码风格一致的变量和文件命名；
- 为兼容现有框架所需的等价技术实现。

Codex 不可以自行决定：

- 更换项目排序；
- 把 PayTrace 提升为重点项目；
- 修改首页区块顺序；
- 重写文案方向；
- 换配色或强调色；
- 增加头像、渐变、3D、轮播、鼠标特效；
- 删除 Terminal、DevMode 或 `/en`；
- 用新 UI 框架覆盖现有系统；
- 为填满页面虚构内容；
- 未经验证修改测试数字；
- 改变简历稳定路径。
